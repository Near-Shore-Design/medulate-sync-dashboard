Rig internals

The whole system

Four processes run on the rig PC. The tracking server owns the hardware and streams poses to Unity over localhost UDP. Unity renders the procedure and hosts the kiosk UI in an embedded browser, which is the only part that talks to the cloud for trainee data.

Tracking pipeline

What happens to a raw sensor reading before Unity sees it. The offsets and the needle lever arm are the values the calibration wizard produces.

Control box optical channel

Two colour sensors along the wire channel turn wire position into a depth, and colour temperature tells a catheter from a guidewire.

Serial commands · firmware DHRT_rawC_color

SendReply or effect
r · sLED mode · sensor mode (the guidewire step sends s twice)
a · b · cred · blue · LEDs off
dsyringe switch pin state
qC I D flags: catheter, wire inserted, wire deep
k · praw colour readings · current thresholds
w gw empty cath ctmin ctmax latch clearwrite thresholds to EEPROM, replies THR OK
xerase EEPROM, replies THR RESET

One training run, message by message

Access Vein followed by Catheter Placement, the two graded lessons. The kiosk is the only thing that writes trainee progress to the API; Unity only reports what happened.

Needle step state machine

AccessVeinTest decides when an insertion counts, when the needle is in the vein, and every way the step fails.

Catheter walkthrough

Seven steps in a fixed order, fed by the optical sensors, CV and on-screen Done buttons.

Scoring

How NeedlePerformance turns a run into the 0 to 1 score the kiosk grades. The weights come from the active scoring rubric on the API.

Trainee journey

The API enforces every gate below and the kiosk mirrors it from dashboard.progression, so a lock looks the same in the UI as it does on the server.
